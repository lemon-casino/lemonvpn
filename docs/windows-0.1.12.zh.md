# Windows x64 0.1.12：按页面顺序的代码排查

## 范围

按“活动 → 状态 → 策略 → 节点 → 连接 → 分流 → DNS → 规则 → 日志 → 事件 → 配置”的顺序，核对页面入口、数据投影、接口字段、能力声明和后端实现，修复静态检查中能确定的问题。

本轮没有迁移为纯 mihomo 后端。系统代理和 TUN 的开关、路由及现有服务没有在本机执行操作；TUN 相关修改限于内核文件名引用、状态说明和连接记录。未运行测试、启动新客户端、修改当前用户配置、安装更新、切换网络、休眠或重启服务。编译通过不能替代运行验收。

## 内核命名

| 目标平台 | 内核可执行文件 |
| --- | --- |
| Windows | `lemonvpn-kernel.exe` |
| macOS | `lemonvpn-kernel` |
| Linux | `lemonvpn-kernel` |

- 当前仍下载 mihomo 官方固定版本 ZIP，校验已固定的 SHA256，提取并以新名称打包。上游项目、版本、许可证和摘要继续在清单中保留，改名不代表自研内核。
- 构建脚本与 Rust 运行时集中定义文件名；Windows 安装包资源映射、开发构建副本和服务安装/启动使用同一名称。
- 清除桌面启动器隐式优先查找 `honk-core` 的旧入口，保留显式开发环境变量覆盖。
- 本轮只构建 Windows x64。macOS/Linux 仅统一命名约定，不代表其系统集成或安装包已完成；其他平台暂不考虑，Windows ARM64 和正式发布继续延后。
- 本轮不会替换已安装的服务；新包的服务资源路径使用新内核名。升级后如界面提示服务需更新，可通过原有安装/修复入口处理。

## 逐项排查与处理

| 页面 | 代码核对与修复 |
| --- | --- |
| 活动 | 核对流量采样、历史、出站分布、节点状态和通知的数据来源。连接现在返回真实出站与代理链，按出站统计的投影不再把代理连接算为直连；配置与操作通知有实际事件可读。 |
| 状态 | TUN 协议说明按后端 `full` / `dns_only` 能力显示；配置生效时间使用配置快照时间；暂停时数据路径标记为禁用；内存明确标注为 Rust 后端进程指标，不冒充包含代理内核与界面的整套软件内存。 |
| 策略 | 配置接口与现有全部策略解析方式统一；按真实策略区分手动选择和临时固定能力。JSON Patch 不依赖字段顺序，先完整校验，正确执行 test，规范默认成员 ID；修改策略时保留默认成员与兜底设置。健康缓存同时比较错误和测量方式，避免错误说明停留在旧值。 |
| 节点 | 订阅名称支持中文、字母、数字及常用连接字符，与界面校验对齐；共享 JSON 解码正确处理 Unicode 与转义。订阅、节点数据改为完整临时文件替换，保存失败回滚内存并返回错误；删除节点不再重复解码 ID。探测请求对象和数组使用 JSON 解析。 |
| 连接 | 在建立连接时保存实际路由决定，包括出站、节点/组 ID 链、域名、命中规则及流程 ID；后续策略变更不会重新解释旧连接。移除固定返回 `direct` 的占位内容；IPv6 来源筛选正确解码。补齐批量关闭接口，按协议和来源限定范围；超过 1000 条先拒绝、关闭零条，由界面拆分请求；需要显式 `all=true`。 |
| 分流 | 流程与连接互相关联，按连接筛选使用真实连接 ID；列表携带目标地址与域名。IPv6 地址保留方括号；拨号阶段和已连接阶段分开。分页使用最多 8 份、有效期 30 秒的快照；过期游标明确报错。录制开关、容量与保留时间落实到记录器。 |
| DNS | 查询按接口约定读取 `type` 数组，兼容旧 `types` 字段；选中的记录类型不会静默变为 A。请求规则支持 qname/domain、qtype 及组合，查询和转发使用匹配的上游。缓存按上游与配置代次隔离，TTL 为零、空响应及错误响应不作为正缓存写入。查询成功进入 DNS 记录，录制开关和容量生效；修复过期缓存查看、域名及 IPv6 筛选编码。 |
| 规则 | 编辑器只提供当前 LemonVPN 后端实现的条件。保留已实现的域名、IP、端口、协议和 DNS 请求条件；不再引导用户应用后端不支持的 GeoIP/GeoSite/进程条件模板或 DNS 响应规则。包含文件中的规则使用正确源 ID 和行位置。 |
| 日志 | 录制开关、按需录制、日志级别在写入记录器时生效；设置页返回真实缓冲记录数和当前录制状态。日志流游标与实际引擎实例绑定。 |
| 事件 | 补入操作运行、完成、失败以及配置代次变更事件。实例 ID 包含启动时间，避免进程 ID 重用后误接续旧日志、事件和连接快照。未实现的逐流程事件不声明为可用。 |
| 配置 | 正确解析 1～4 份候选源，校验路径、ID、大小与语法，候选内容参与 include 校验而不写盘。写入前再次校验，并在串行提交时检查文件版本；使用原子替换，拒绝错误内容。主文件与 include 文件均可按版本写入；include 使用稳定、不携带文件名的源 ID。生效快照保留已加载内容，单源读取反映磁盘内容，便于处理外部修改。无效重载保留旧快照，记录拒绝信息。 |

运行时设置先完整校验再合并提交，避免后半项失败却已应用前半项。`auto` 录制模式按相关页面或日志流的读取需求保持 30 秒的记录窗口；没有相关读取时停止新的按需记录。

查询参数与路径参数分开解码，含空格的组名和 IPv6 筛选不再因 URL 编码失配；百分号后跟 Unicode 等非十六进制内容时保留原文，避免解码时切断 UTF-8 导致异常。

## 仍需明确的能力边界

- 当前前端适配的是 LemonVPN 原生 API，协议兼容与标准 Windows TUN 仍使用 mihomo；本轮没有把规则、DNS和策略业务整体迁入 mihomo。
- 原生规则层尚未实现 GeoIP/GeoSite 条件、进程条件和 DNS 响应规则。相应模板入口及可选条件已收敛；原始配置写入这些未实现条件时应拒绝，而非假装已应用。
- 连接来源是用户态入口实际观察到的来源。TUN 转发后的来源不等于原始应用来源；未增加原生进程归属采集。
- 内存指标统计范围已经说明；CPU、进程归属及未实现的详细流程追踪不编造数值。日志页主要展示 LemonVPN 后端日志，不等于合并了 mihomo 的全部内部日志。
- 外部直接修改 include 文件后，仍应执行重载使其生效；应用中的源文件写入会重新构建生效快照。

本轮验证限定为 TypeScript 类型编译、Rust 编译及 Windows x64 安装包构建，不运行测试或新程序。完整构建日志、SHA256 和构建记录位于 `app/src-tauri/target/`。

安装包：`app/src-tauri/target/release/bundle/nsis/LemonVPN_0.1.12_x64-setup.exe`。
