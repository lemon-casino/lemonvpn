# Windows x64 0.1.22：规则体验、DNS 动作与桌面弹框

## 本次只读观察

用户截图的规则是 `domain(full: youtube.com) -> US`。实际已有连接记录中的目标是 `www.youtube.com:443`；域名保留在 TUN 桥接后的连接记录中，并未丢失。完整域名条件只比较完全相同的名称，因此这条规则不能覆盖 `www.youtube.com`。浏览器页面还可能使用其他后缀的视频、图片域名，单独一个完整域名不足以表达整个网站的分流范围。

只读观察时，用户已切为全局模式，已有连接实际显示 US 出站；没有替用户切换模式或改写当前规则。读取了既有版本、运行状态、TUN、规则、连接、流程记录、DNS 记录和配置中的上游地址，未执行 DNS 查询、路由追踪、测速或网站访问。该观察不能代替新版本的运行验收，也没有据此断言某个 DNS 答案受到污染。

## 规则范围与新建入口

快捷新建默认使用域名后缀，保留完整域名、关键字等其他选择。完整域名规则在列表及编辑表单中说明其不包含子域名；后缀规则说明包含域名本身及子域名，其他后缀需要另行添加规则或使用 GeoSite。

LemonVPN 适配器为已知的 YouTube 域名提供显式可选的 `domain(geosite: youtube)` / `qname(geosite: youtube)` 条件。不会自动修改已有规则，也不自动扩大已保存规则的范围。本地打包的 youtube 分类含 178 个条目，已通过读取资产确认包含 youtube.com、youtu.be、googlevideo.com、ytimg.com、youtube-nocookie.com；没有请求在线数据或运行内核测试。

共享引擎不支持的 `(must)` 出站修饰选项从原生规则表单隐藏，其他引擎继续按适配器能力显示。

## 模式表达式固定在普通规则之前

在全局或直连模式下，自动生成的模式表达式保持优先。规则页和连接、DNS、追踪等快捷新建入口均排除其前面的插入位置；最前选项明确称为“普通规则最前（模式规则之后）”。无法通过“命中规则之前”选项绕过模式前缀。

直接插入与暂存批量写入都检查当前文本中的模式标记边界，阻止旧对话框、旧暂存项或过期位置越过该前缀。普通规则排序继续保持模式规则与 fallback 固定。配置原文编辑仍是显式源文件编辑，不属于新建规则表单的插入操作。

模式内新建的普通规则可以保存；切换为规则模式后才参与分流。界面为此提供说明，不将保存成功解释成已经覆盖全局模式。

## 区分模拟、节点探测和实际连接

追踪不再只返回最终匹配的一行，按优先级返回已检查的规则，区分未匹配、匹配与输入缺失。缺少目标 IP、来源、进程等输入时，不再把无法排除的早期条件跳过并错误地报告 fallback 已确定；取反及组合条件保留相应未知状态。

追踪中的“连通性”改为“节点探测延迟”。已有节点探测数据并不证明追踪中的目标网站可达，页面明确说明模拟不会访问目标网站，实际路由需要查看“活动 → 连接”。

DNS 查询页面明确区分 DNS 上游规则和连接出站规则。DNS 查询及 DNS 日志保存当次查询的真实路由来源、命中表达式或显式指定上游，修复日志一律显示 default 的问题；查看历史记录不会拿新配置重新标注旧结果。

## 内置出站与 DNS 动作说明

规则出站选择、策略组最终出站、列表及共用出站标签显示 `direct（直连）`、`block（拦截）`；配置标识及表达式继续使用原来的 direct/block。

DNS 请求规则保留选择上游、reject（空结果）；响应规则保留 accept（保留应答）、reject、通过另一上游重新查询。动作选择有说明文字，并增加 nxdomain（域名不存在）、refused（拒绝查询）、servfail（解析失败），分别生成 RCODE 3、5、2 的空应答，定义参照 [IANA DNS RCODE 注册表](https://www.iana.org/assignments/dns-parameters#dns-parameters-6)。请求阶段的这些动作直接应答，响应阶段将收到的应答替换为所选状态。原有 reject 继续使用 NOERROR 空结果。

新增状态在原生 API 仍归为 reject，并通过 `x-lemonvpn-action` 保留具体动作，避免编辑、排序、保存时退化为普通空结果。表单选项、配置校验、查询处理、响应处理、默认动作及回读均接入；DNS 上游名称拒绝与保留动作冲突。响应规则也处理上游的错误应答，允许按条件改用另一上游重查，仍保留循环限制。未提供没有实现的 asis 原始目标转发。

## 隐藏滚动条与完整遮罩

桌面端所有页面、侧栏、表格、弹框及编辑器隐藏原生滚动条，滚轮、触控板、键盘和内容滚动能力继续保留；没有把全局 overflow 改成 hidden。浏览器模式沿用原有样式。

定位到共用弹框的 React Aria 滚动锁会在根元素写入 `scrollbar-gutter: stable`，使右侧保留没有遮罩的滚动条槽。桌面样式统一取消这类占位，共用 underlay 使用完整视口宽高和四边定位，覆盖确认弹框、表单、抽屉等使用该组件的入口。底层已有 body Portal 路径保持不变，保留焦点管理和背景滚动锁。
