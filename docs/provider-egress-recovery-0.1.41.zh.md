# 订阅更新与出站恢复（0.1.41）

## 现象与边界

订阅刷新报 `fetch_failed`，错误末尾为“基础设施出站不可用”；用户确认节点在其他软件中可用，并且重装后恢复。

该错误发生在出站解析阶段，不能据此认定节点服务器故障。重装附带的软件、引擎重启会清理进程中的组健康状态和 DNS 连接池，能够解释暂时恢复；尚未取得报错时的完整运行时状态，不能把这一解释当作历史故障的唯一结论。

只读检查当前配置确认，代理域名解析使用通过 `US` 出站连接的 DoH 上游。代码排查发现：

- 默认直连订阅下载仍使用普通业务 DNS 分流。
- 节点健康检查解析节点地址时，也使用同一业务 DNS。
- 自动组会排除 HTTP 检查失败的节点；全部被排除时无法选出出站。业务 DNS 又可能依赖该组，因此可形成循环依赖。

## 修改

1. 所有引擎 HTTP 下载在公共入口启用独立引导解析，覆盖订阅、规则集与地理数据。保留原下载出站和 TLS 验证，不因指定代理失败而改走直连。
2. 节点检查的地址解析使用已配置的引导 DNS。地址解析失败、没有对应地址族等前置条件不足时记录为 `unknown`，不将其写成节点连接失败。
3. 自动选择优先使用检查正常或尚未知晓的成员。仅当这些候选全部不可用时，允许在组内选择成员进行实际连接恢复；真实连接失败仍保留十秒退避。空组、失效引用或无效链路仍明确失败。
4. DNS 和下载的指定出站连接复用普通连接反馈。实际连接成功可以恢复组成员资格，不只依赖固定检查网站。
5. DNS 查询错误附带上游名称和出站名称。出站解析错误区分不存在、没有匹配节点、链路成员未选出、连接失败后的退避期，不再只有模糊的“基础设施出站不可用”。

这些调整不会修改已保存的 DNS 分流、策略组、订阅或健康检查网址，也不会自动切换用户选择的出站。
