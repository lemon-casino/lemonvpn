# Rule Provider、Geodata、DNS 与 Fake-IP 联动实施方案

日期：2026-11-10。状态：已完成本轮源码实现与构建；实际入口、接口和边界见 [交付说明](rules-dns-fakeip.zh.md)。本文保留实施前设计。

实施只修改源码、静态检查和构建，不运行测试、不启动新客户端、不安装服务、不修改当前客户端的数据、系统代理、TUN 或防火墙；不自动提交、打 tag 或发布。

## 1. 管理原则与交付目标

沿用 LemonVPN 已确定的交互方式：

1. **资源管理一次，多处引用。** 规则集、GeoSite/GeoIP、DNS 上游各有唯一 ID；路由、DNS、Fake-IP 引用它们，不复制出三套可独立修改的数据。
2. **资源和动作分开。** “YouTube 规则集”表示匹配哪些请求；走哪个出站、使用哪个 DNS、返回哪类地址由使用处决定。修改资源名称不破坏引用。
3. **复杂编辑一次应用。** 弹框内修改为草稿，点击“保存并应用”后统一写入、生效；页面选择、预览和拖动过程不提前切换真实网络。沿用活动页与小工具现有各自的应用语义。
4. **快捷动作少点击。** 单个启停、更新、列表松手排序可以直接提交，有忙碌状态和失败回退；不增加“排序弹框”。
5. **引用删除一次处理。** 删除规则集、上游或出站时列出引用，弹框可选择替换对象或移除相关引用，整批提交，失败全部保持原配置。
6. **显示实际状态。** 区分编辑草稿、下载成功、校验成功和运行生效；错误不显示成功，不将模拟路径当成真实连接。
7. **默认界面简单。** 日常操作提供中文字段与常用分类；格式、请求头、地址族和引导解析放入高级项。卡片位置稳定，遮罩覆盖整个窗口，保持现有隐藏滚动条但可滚动的行为。

最终交付是：可视化规则集管理、可复用地理分类、国内外 DNS 策略、DoH/DoT、统一缓存和追踪，以及跨进程确认的热更新。完成后重新构建 Windows x64 安装包；共享代码同时覆盖 Windows/macOS/Linux，六目标构建流程保留。

## 3. 页面设计

### 3.1 规则页面

标签顺序：**路由规则｜规则集｜地理数据｜DNS 规则｜追踪**。保留原路由与参数的兼容跳转；“路由规则”页内的已有简易/高级视图继续使用。

| 标签 | 管理内容与交互 |
|---|---|
| 路由规则 | 继续管理顺序和出站；新建条件增加“规则集”“GeoSite 分类”“GeoIP 地区”；支持直连、阻断、策略组、链式代理 |
| 规则集 | 列表显示名称、来源、类型、条目数、更新时间、运行版本及引用数；操作为新增、编辑、启停、更新、查看内容、删除 |
| 地理数据 | 显示 GeoSite/GeoIP 来源、摘要、更新时间；可搜索分类、查看样例和被哪些规则引用；选中分类后创建分流或 DNS 规则 |
| DNS 规则 | 保留请求/响应规则，新增规则集条件和解析池选择；保留重置默认、行内拖拽与错误定位 |
| 追踪 | 合并显示规则命中、DNS 选择、缓存、Fake-IP 与最终出站；保留离线分析和明确的实时查询入口 |

规则集“新增”支持粘贴 URL、选择文件、粘贴内容。自动识别格式和匹配类型；识别不明确时显示识别结果与待补字段，不猜测后直接应用。文件导入默认复制进应用数据目录，更新不依赖原文件仍然存在；持续读取原路径属于高级选项。

规则集只显示分页/搜索后的条目，不把几十万条内容一次渲染到页面。来源 URL 隐藏凭据；高级请求头不进入错误复制、日志和普通导出。

### 3.2 DNS 页面

标签顺序：**策略｜上游｜Fake-IP｜缓存｜查询｜记录｜统计**。

- “策略”统一配置国内直连、代理域名、局域网、节点引导和未分类域名的处理方式；每个预设展开后就是可以编辑的真实规则。
- “上游”管理 DNS 服务器和解析池，展示协议、连接出站、引导地址、真实查询成功率和耗时。主备服务器均在同一池内管理。
- “Fake-IP”保留地址池和持久化，增加“跟随分类策略”和显式例外；展示已应用的排除/匹配策略及引用。
- “缓存”显示真实 DNS 缓存与 Fake-IP 映射两个独立视图，分别清理，不把二者混为一谈。
- “查询”输入一次域名，可查看命中规则、选用上游、缓存来源和真实/Fake-IP 结果。实时查询仅由用户主动触发。

地理数据的编辑入口统一放在规则页。设置页原入口保留摘要和跳转，配置页模块卡片也指向同一资源，不再出现多份编辑器。

## 4. 数据模型和唯一版本

新建 `RulesRuntimeSnapshot`，由一个 coordinator 发布不可变快照：

```text
配置源 + 用户规则 + 规则集设置/已接受内容 + Geo 摘要
       + DNS 上游/策略 + Fake-IP 策略 + 出站引用
                         ↓ 校验、编译
       RulesRuntimeSnapshot（唯一 active_generation）
             ├─ Rust 路由匹配
             ├─ Rust DNS 策略、缓存与追踪
             └─ 受限的 TUN Fake-IP 策略产物
```

主要对象：

- `RuleSet`：稳定 ID、显示名、启用状态、来源、behavior、format、更新周期、下载出站、可选期望 SHA256、引用关系。
- `AcceptedAsset`：内容摘要、条目数、格式版本、最后成功时间、ETag/Last-Modified、当前接受版本、失败原因。
- `GeoCategoryRef`：资产种类、分类及属性、资产摘要；不靠 UI 显示文字充当身份。
- `ResolverEndpoint`：UDP/TCP/DoH/DoT、端点、TLS 校验名、bootstrap IP/引导池、连接出站及超时。
- `ResolverPool`：成员 ID、主备或有界竞速、失败策略；不能把不同隐私策略的上游放在同一竞速池。
- `DnsPolicy`：稳定 ID、顺序、可用条件、解析池、地址处理（真实/Fake-IP/沿用）、显式例外和来源。
- `TraceResult`：配置版本、资源摘要、匹配依据、缺失条件、DNS 各阶段、地址类型、有效出站和运行/模拟标志。

持久化采用“版本目录 + 原子 active 清单”，以现有 `storage.rs` 原子写为基础；清单同时记录配置、资源与 DNS 设置的摘要。启动只加载最后完整提交的版本，未完成事务留在暂存区并清理。外部规则内容不展开写入有 64 KiB 限制的 `config.dae`。

配置文件继续可读写；新增稳定引用语法的首版形式为 `ruleset('rs-稳定ID')`，交给现有条件 AST 编译。编辑器、表单和导出指向同一配置对象，不建立“表单另存一份、原始配置又存一份”的双重来源。旧文件原文、注释和用户规则不被自动重写成预设。

## 5. Rule Provider 与 Geodata 的完整接入

### 5.1 格式与匹配

| 行为 | YAML / Text | MRS | 可引用位置 |
|---|---|---|---|
| domain | 支持 | 支持 | 路由、DNS 请求、Fake-IP 域名策略 |
| ipcidr | 支持 IPv4/IPv6 | 支持 | 路由、DNS 响应中的真实 IP 判断 |
| classical | 支持现有引擎可表达的条件及组合 | 不支持 | 按具体条件判断；只有纯域名部分可显式用于 DNS/Fake-IP |

上述格式范围对应 [mihomo Rule Provider 文档](https://wiki.metacubex.one/config/rule-providers/)。MRS 解析以仓库固定的内核版本为兼容基准，检查头、版本、长度、解压上限和索引边界；不靠启动另一个内核执行转换命令。

classical 必须在导入前列出不支持的行与原因，整份拒绝并保留上次可用版本，不静默丢掉不认识的规则。首版覆盖域名精确/后缀/关键字/正则、IP-CIDR/IPv6、GeoSite/GeoIP、来源 IP、端口、网络协议、进程及 AND/OR/NOT；超出实际平台或当前 AST 能力的类型明确显示不可用。

混合集合用于 DNS 时不能把包含端口、进程等条件的复合表达式简单删除条件后放大匹配范围。默认只允许已证明为纯域名表达式的集合；需要域名子集时，由用户明确选择“仅使用域名部分”，预览哪些条目会被排除。

资源能力返回 `routing / dns_request / dns_response / fakeip` 的适用范围，选择器据此筛选。Fake-IP 域名组合若无法在固定内核中无损表达，则禁止该用途并定位原因；路由和 DNS 原条件仍保留，不能通过近似展开冒充兼容。

规则集内部不指定最终出站；最终动作由引用规则决定。资源循环引用禁止，稳定 ID 去重；源文件自带动作的兼容导入必须预览转换，不能在后台悄悄覆盖用户出站。

### 5.2 生命周期

流程：下载/读取 → 临时文件 → 验证来源响应与内容 → 解析编译 → 引用检查 → 生成差异 → 热应用 → 接受新版本。

- 增量更新支持 ETag/Last-Modified；内容未变不生成新版本、不清缓存、不重建连接。
- 周期任务采用抖动与失败退避，断网保留最后成功内容，恢复后再调度；主界面不开启周期测速。
- 期望 SHA256 存在时进行匹配校验；只有计算摘要但没有可信期望值时，只能说明内容身份，不能显示“已通过官方完整性校验”。
- HTML、HTTP 错误页、格式错误、未知分类和截断文件不得替换有效资源。
- GeoSite/GeoIP 与规则集共享下载、版本、引用与回滚基础设施；复用现有分类解析，不重复创建另一套互不一致的分类库。
- 删除或停用有引用资源时显示影响清单，可一次性替换；不能产生悬空引用。替换必须匹配用途，例如 IP 集合不能替代 Fake-IP 的域名集合。

初始资源上限：64 个启用集合、单源下载 16 MiB、解压后 64 MiB、单集合最多 100 万条、并发下载 2。Geo 资产继续沿用现有受限路径。上限在能力中返回，超限明确报错，不截断后假装成功；运行匹配不展开成逐条扫描。

## 6. 国内外 DNS 分流与优先级

国内外是可编辑的分类策略，不是“IP 在中国就一定国内服务”。优先使用明确域名与 GeoSite/域名规则集；GeoIP 只在已有真实 IP 时辅助判断，不能用尚未得到的 IP 决定最初应该问哪个 DNS。

| 优先级 | 匹配对象 | 默认建议（仅在用户启用新预设后生效） |
|---|---|---|
| 1 | 用户显式 DNS 例外与 hosts | 完整尊重用户设定 |
| 2 | 局域网域名、内部域名、反向解析 | 使用网络对应 DNS，真实地址；mDNS `.local` 不伪装成普通公共 DNS 查询 |
| 3 | 明确拒绝的域名集合 | 按明确配置返回拒绝结果；不制造不存在的公网地址 |
| 4 | 用户指定服务、规则集、GeoSite 分类 | 使用指定解析池与地址模式 |
| 5 | 国内直连分类 | 国内解析池，优先适合本地 CDN 的结果 |
| 6 | 代理分类 | TUN 中优先 Fake-IP；确需真实解析时使用经指定出站的加密解析池 |
| 7 | 未分类域名 | 使用用户选择的默认池与地址模式，不把“未分类”偷偷当成“国外” |

兼容旧 DNS request/response 规则：旧规则迁移为显式用户规则并保持顺序，优先于新增预设；响应的接受、拒绝、换上游重查继续使用真实支持的动作，不重新显示没有实现的 `asis`。

路由全局/直连模式仍在现有受保护的最高优先级，普通规则和拖拽不能绕过。DNS 的解析池与流量出站是不同维度，界面并排展示：例如国内 DNS 解析不等于流量一定直连。选择“跟随有效出站”时按应用后的模式计算，不使用活动卡片中仅供显示的预览选择。

对于进程、端口、来源等 DNS 阶段未知条件，追踪显示“等待连接条件”，连接发生后再做最终路由；不在 DNS 阶段编造结论。若 IP 规则需要解析，则遵循是否允许解析的配置，防止为了无关 IP 规则提前解析每个代理域名。

## 7. 加密上游与引导解析

首版必须完成 UDP、TCP、**DoH（HTTPS DNS wire POST）与 DoT**；DoQ、DoH3 作为后续协议优化，不纳入本次完成声明。

- DoH 首版采用有界 HTTP/1.1 keep-alive 池，DoT 使用有界 TLS 连接池；不能直接把现有每次 GET 都关闭连接的 `fetch.rs` 当作加密 DNS 实现。HTTP/2 多路复用留在接口后续扩展，不阻塞首版。
- 复用 rustls 与现有可信根；验证证书、主机名、HTTP 状态、响应类型、长度和 DNS 问题匹配；不提供默认跳过证书校验的开关。
- 每个端点可指定直连、策略组或链式代理；拨号继续经过 `Platform` 出口保护，避免 TUN 回流。不使用绕过平台保护的通用 HTTP 客户端默认连接器。
- DNS 服务器域名使用配置的 bootstrap IP 或独立引导池解析；节点服务器域名使用独立节点引导池，二者不能依赖自己尚未建立的代理。
- 编译时检查“解析池 → 出站 → 节点域名 → 引导池”的依赖图；发现循环拒绝应用，并在表单中标出循环路径。
- 直连国内与经代理国外的请求不能无条件竞速，也不能因为加密上游失败就悄悄改问系统明文 DNS。降级需要用户明确配置，并记录在查询结果中。
- 池内支持主备及最多两个同策略上游有界竞速；A/AAAA 独立查询与缓存，只使用完整且合法的响应；纯 IPv6 网络保留可用的引导与出站。

Mihomo 具有按分类选择解析器、节点引导解析和指定查询出站的对应概念；LemonVPN 的具体实现仍由共享 Rust DNS 路径统一负责。[官方 DNS 文档](https://wiki.metacubex.one/config/dns/)

## 8. 缓存与查询加速

### 8.1 统一路径

实际 TUN 的真实 DNS 上游转发、直连解析、诊断查询调用同一个 `Resolver`。首版明确采用双层缓存协调：影响 DNS 的策略提交和网络代次变化时，调用内核现有 `POST /cache/dns/flush` 并等待确认，不依赖尚未核实的“关闭内核缓存”参数；Fake-IP 映射池单独保留。Rust 缓存、内核真实回答缓存和 Fake-IP 映射分别标明作用范围；无法观测的内核命中显示“未提供”，不伪造覆盖全部 DNS 的总命中率。

实现正向响应缓存、NXDOMAIN/NODATA 负缓存、同问题在途请求合并。负缓存按 SOA 及 RFC 2308 的语义计算；超时、连接失败与 SERVFAIL 不当作 NXDOMAIN 长期缓存。[RFC 2308](https://www.rfc-editor.org/rfc/rfc2308.html)

缓存键包括规范化域名、QTYPE/QCLASS、影响回答的 DO/CD/EDNS 选项、解析策略版本、上游池、出站及网络代次。涉及 Cookie、ECS 等无法安全共享的请求应按语义隔离或跳过共享缓存，不能直接复用原始查询 ID。回包更新 ID、请求大小写与各 RR 剩余 TTL，保留 CNAME、Authority、Additional 和未知记录；无法安全重写的报文不缓存。

### 8.2 默认参数和失效

- 默认 4096 条、最多 16 MiB；高级上限 20000 条/64 MiB，达到上限按 LRU 淘汰。
- 尊重有效 TTL，不默认把短 TTL 拉长；TTL=0 不缓存。
- 预取只针对已被真实访问的热点项，设置并发和 QPS 上限，不批量预查整份规则集。
- 过期应答兜底为可选高级项，默认关闭；仅上游不可达时短时使用合适的旧正向结果，返回短 TTL，不复用过期签名的 AD 信任标记。不能宣称新增了完整 DNSSEC 验证。[RFC 8767](https://www.rfc-editor.org/rfc/rfc8767.html)
- 修改规则/上游/出站后按依赖失效；网络变化、休眠恢复增加网络 epoch 并重建相关传输连接池。
- 在途回答携带旧 generation 时不可写回新缓存；在途合并也以策略版本隔离。

统计展示真实缓存命中、请求合并、上游请求、成功/失败、P50/P95 与各阶段耗时。没有样本显示“暂无数据”；不承诺未经测量的固定加速比例。

## 9. Fake-IP 联动与特权边界

现有固定内核 `v1.19.33` 已有 `fake-ip-filter-mode: rule` 及域名集合引用；IP 集合不能用于决定返回 Fake-IP。以固定版本源码约束接入范围，不照搬最新文档里尚未核对的参数。[固定版本实现](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/config/config.go)

实现 `FakeIpPolicyCompiler`，把共享快照中的**域名可判定部分**生成内核可消费的有序策略：

1. 用户真实地址例外、内部域名优先。
2. 明确域名分类按用户的真实/Fake-IP 设置处理。
3. 跟随出站只处理 DNS 阶段可确定的域名规则；包含进程/端口等条件时保留连接阶段判断，不能通过删除未知条件扩大匹配。
4. 最终地址模式由用户设定；全局 redir-host 仍可选，不强制开启 Fake-IP。

Rust 使用原始已接受资源编译路由和 DNS；内核仅收到同一摘要衍生的域名投影。对于 GeoSite 与 classical，导出保持精确/后缀/关键词/正则语义的规范化产物，不能把 regex 误转换为后缀。

管理员服务协议升级到有能力协商的新版本：只接受白名单设置和有界、带摘要的域名资源产物；分块传输与最终摘要核对，服务写入自己固定目录下的 revision 文件。**不接受用户提供的任意路径、下载 URL、可执行命令或整份内核配置。** 内核不自行联网更新另一份规则集。

普通分类调整保留不受影响的 Fake-IP 映射；不得每次更新规则集就清空整个映射池。模式/地址池变更单独处理映射迁移、系统缓存协调与受影响 TUN 会话；无法无缝保留旧池时在应用结果中明确报告影响，不伪装成零中断。普通规则更新不需要改变地址池。

Fake-IP 作用范围继续明确标示：只有实际 DNS 请求经过可返回 Fake-IP 的入口才生效。系统 HTTP/SOCKS 代理和新局域网代理端口不代表设备 DNS 已被接管。本次不默认开放局域网 DNS 监听，也不把设备指向 Fake-IP DNS 后留下一条不能承载对应流量的路径。

## 10. 热更新事务与现有连接

引入统一的 `prepare → validate → stage → apply → commit` 操作，更新结果返回 `active_generation`、应用范围、受影响连接和同步错误。

1. 在后台准备资源与候选快照，长下载不持有全局配置锁。
2. 校验资源引用、条件适用性、出站、解析依赖图及内核能力；冲突返回 409，保留草稿。
3. 写完整的不可变 revision 和恢复清单。涉及 TUN 的事务短暂阻止受影响的新 DNS/路由决策穿过新旧版本边界，已有无关流量继续工作。
4. 必要时下发受限域名产物和 Fake-IP 设置，等待内核确认具体版本与摘要；内核不存在且 TUN 未开启时，记录下次启用所需的已提交版本。
5. 发布 Rust 快照和 active 清单，切换依赖缓存与连接池，解除短暂等待；管理 API 全程可达。
6. 重新判断受影响的活动连接：出站或强制阻断结果改变的 TCP/UDP 会话立即退役，让应用按新规则重连；不相关连接保持。TLS/TCP 流不能在不重连的情况下迁移节点。
7. 发出统一事件，所有页面、小工具、连接追踪和配置摘要更新到同一 active_generation。

这不是多个进程在同一 CPU 指令里切换：短暂决策屏障、版本确认和恢复日志用于避免可见的不一致。设定有界等待和请求队列；超过期限失败回退，不能无限挂住界面。

| 失败点 | 行为 |
|---|---|
| 下载、解析、引用或证书失败 | 不进入应用；继续使用最后成功版本 |
| 资源写入或磁盘不足 | 不改 active 清单与运行版本 |
| 内核拒绝/确认超时 | 恢复旧产物与设置，不显示成功；列出真实同步错误 |
| 部分应用后恢复也失败 | 标为“未完全应用/需处理”，公开当前各组件版本；不谎称已经回滚完成 |
| 应用时发生并发编辑/自动更新 | 一个提交序列器；基于修订合并或拒绝冲突，不覆盖较新用户修改 |
| 崩溃或重启 | 从完整提交清单恢复，丢弃未提交 revision，必要时恢复旧内核派生设置 |

既有连接的退役安排在发布成功后，不把已经关闭的网络连接列为可回滚的数据。热更新保证立即使用新策略并处理相关旧连接，不保证应用无感重连。

## 11. 追踪：一条路径说明全部依据

规则页追踪与 DNS 查询共用服务，输入域名可附带协议、端口、来源和进程。默认离线分析不发 DNS 或网站请求；实时 DNS 查询和实际连接记录单独标示。

追踪逐步展示：

```text
请求域名 / 入口 / 配置版本
  → 显式规则、规则集或 GeoSite 分类（来源、条目、资源摘要）
  → DNS 请求策略与解析池
  → 缓存命中 / 在途合并 / 实际上游及直连或代理路径
  → DNS 响应规则与必要的重查
  → 真实地址或 Fake-IP（池、映射状态）
  → 有效出站：直连 / 阻断 / 策略组 / 链式代理
```

“未命中”“缺少进程/端口”“未进行实际查询”“已被全局模式覆盖”分别显示。真实连接保留建立时的快照，不能用后来切换的节点覆盖历史路径；活动页继续显示当前已应用出站和真实流量，不另增加独立选择。

## 12. API、事件与兼容迁移

以下为首版拟定接口，实现前与前端类型一次锁定：

| 接口 | 职责 |
|---|---|
| `GET/POST /api/v1/rule-providers` | 列表、添加资源；写入携带配置修订 |
| `GET/PUT/DELETE /api/v1/rule-providers/{id}` | 编辑、删除与引用替换计划 |
| `POST /api/v1/rule-providers/{id}/refresh` | 启动后台更新操作 |
| `GET /api/v1/rule-providers/{id}/entries` | 分页搜索及条目来源 |
| `GET /api/v1/rule-providers/{id}/references` | 路由/DNS/Fake-IP 引用清单 |
| `GET /api/v1/geodata/categories` | 分类分页、属性和检索 |
| `GET/PUT /api/v1/dns/resolvers` | 端点、解析池及依赖校验 |
| `GET/PUT /api/v1/dns/policies` | 分类与地址策略，批量草稿一次应用 |
| `POST /api/v1/dns/trace` | 统一的离线分析/明确的实时 DNS 查询 |
| `GET /api/v1/dns/statistics` | 真实请求、缓存、合并与上游耗时 |
| `GET /api/v1/runtime/apply` | 事务、当前/候选版本、组件同步结果 |

大资源更新使用现有 operation 机制并可取消；取消下载不撤销已提交操作。所有写入接受 revision/expected_generation，长操作具备幂等 ID。

保留 `/dns/query`、`/dns/settings`、已有规则和 Geo 更新接口，适配到统一 coordinator。新 DNS 设置使用能力版本区分 v1 简单域名排除与 v2 资源引用；旧服务不支持 v2 时明确需要更新服务，不先写入不能生效的配置。

事件扩展沿用已有 `runtime.updated`、`generation.changed` 和 `operation.updated`，携带影响域和运行版本；前端按影响失效，避免一次状态变化重拉所有大列表。

迁移默认保留原 UDP/TCP 上游、手写 DNS 规则、模式、Fake-IP 地址池/排除名单/持久化。国内外智能预设需要用户主动选择并预览差异，不在升级启动时替用户更改分流；旧规则顺序、protected 全局表达式和 fallback 位置不变。

## 13. 分阶段改动清单与完成标准

各阶段按依赖顺序实施，分别形成可审查的改动；中间阶段不标记整个功能已完成。

P0 先确定统一提交状态机及核心侧事务入口，P1～P3 接入这一入口，P4 再完成跨进程版本确认。尚未满足端到端条件的写入能力不在 capabilities 中开放，不能把只有页面或资源下载的中间状态作为可用功能交付。

| 阶段 | 主要代码位置 | 可交付内容与完成条件 |
|---|---|---|
| P0 基础模型 | 新增 `engine-core/src/rules_runtime.rs`、`resource_catalog.rs`；调整 `config.rs`、`storage.rs` | 稳定 ID、引用图、不可变快照、revision 清单和兼容迁移；旧配置编译结果保持原语义 |
| P1 规则资源 | 新增 `rule_providers/`（下载/调度/格式/MRS/索引）；增强 `geodata.rs`、`fetch.rs`、条件 AST | YAML/Text/MRS 按矩阵接通；Geo 分类浏览；严格错误定位；更新、停用和引用替换都经过统一事务 |
| P2 DNS 传输 | 将 `dns.rs` 拆为保留兼容导出的 `dns/` 模块，新增 `transport.rs`、`bootstrap.rs`、`upstreams.rs` | UDP/TCP/DoH/DoT、有界池、显式出站、引导依赖检查；所有 socket 受平台出口保护 |
| P3 DNS 策略/缓存 | 新增 `dns/policy.rs`、`cache.rs`、`inflight.rs`、`statistics.rs` | 国内外分类策略、统一 wire 查询、正确 TTL/负缓存、请求合并、网络 epoch；后台不自动做联网测速 |

| P5 可视化/追踪 | `doona/src/features/rules/`、`dns/`、`settings/`、`config/DesktopModules.tsx`、API 类型和资源失效 | 按第 3 节提供完整入口；统一追踪、删除引用批量处理、一次应用与失败保留草稿；中英繁体词条与搜索入口齐全 |

## 14. 静态检查、审查场景与最终交付边界

按用户要求不运行单元、集成、UI、联网、断网、休眠或性能测试，也不为了验收切换正在使用的软件。允许执行 TypeScript、针对修改文件的 ESLint/Stylelint、Rust 编译、补丁应用检查及未签名安装包构建。构建不得触发默认测试脚本。

代码审查和编译时逐项核对以下契约；它们是实现检查清单，不代表已经完成实际运行验证：

- 同一个域名集合在路由、DNS、Fake-IP 中使用同一内容摘要。
- 被引用资源删除、重命名、更新失败时没有悬空引用，也不覆盖有效旧版本。
- 国内分类、代理分类和用户例外按明确顺序决定 DNS；GeoIP 不在无 IP 时制造匹配。
- 节点引导与加密 DNS 没有递归依赖；失败不擅自降级到未配置的明文解析。
- 实际 wire 查询与诊断共用缓存，过期 TTL 不被当成新记录，旧版本回答不能污染新缓存。
- 已应用模式、策略组和链式代理切换同步刷新依赖池与相关会话，不等用户下次手动连接。
- 全局表达式和 fallback 的保护、活动卡片显示语义、小工具布局及现有配置编辑保持一致。
- 无流量时没有虚构 DNS 耗时和连接动画；追踪区分当前预览与历史真实请求。
- 新旧服务能力不同、TUN 关闭和只开系统代理时，页面能准确说明 Fake-IP 的实际作用范围。

最终交付清单：源码与可复现前端补丁、API/能力说明、迁移与恢复说明、上述契约审查结果、静态检查与各平台编译记录、Windows 安装包和 SHA256。运行稳定性与速度提升只能在以后实际测量后下结论，本轮不以编译成功替代性能或真机验收。
