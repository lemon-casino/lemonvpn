# Windows x64 0.1.25：链式代理与链路预览

## 使用入口

策略页增加“新建链式代理”；“新建组／编辑组”中也可以开启“启用链式代理”。选择前置节点或策略组，再选择一个落地节点，保存即可应用。路由规则或全局出站选择这个组后，请求按“本机 → 前置代理 → 落地节点 → 目标”转发。

开启链式模式时，界面用落地节点生成单成员 `fixed(0)` 组，并设置 `dialer`。关闭链式模式后移除 `dialer`，恢复普通组配置。高级配置可将另一个链式组作为前置，最多 8 个物理节点；界面不会导入或执行订阅内任意的 `dialer-proxy` 关系。

```text
group {
  链路 {
    filter: name('落地节点')
    policy: fixed(0)
    dialer: '前置节点或策略组'
  }
}
```

原有普通组的选择策略继续保留；链式编辑保存为明确的单个落地节点，不混用筛选条件、默认成员或后备出站。

## 转发与热更新

- 共享引擎按当前 TCP／UDP 策略解析前置组，保存本次决定使用的全部节点快照。
- 适配层为每个链路快照生成独立的 Mihomo 代理名称，逐跳写入 `dialer-proxy`，从最后一跳的本地 SOCKS 监听进入。不同链路不修改共享节点的引用关系。
- HTTP／SOCKS 入口与 TUN 到本地路由器的入口均使用同一决定。TCP 使用连接，UDP 使用真正的 SOCKS UDP relay；不把 UDP 悄悄改成 TCP 或直连。
- 配置提交仍走已有的完整校验、版本检查、原子写入和统一热更新流程。组的 `dialer` 参与可执行配置比较，改变链路后关闭旧连接，应用可立即重连。
- 连接决定额外记录所有策略组依赖及其 TCP／UDP 选择版本。手动切换前置组时，同时关闭依赖该组的相应传输连接；在变更之前开始的慢拨号也不能重新注册旧路径。
- 循环引用、同名歧义、前置／落地节点集合重叠、无效引用、空前置组、过深或过长链路会被校验拦截。订阅更新导致链路失效时不回退直连。
- 协议能力检查会考虑下一跳建立连接所需的 TCP 或 UDP。未开启 UDP 的节点不能承载需要 UDP 的链路段；受限路径在预览中显示原因，实际拨号同样拒绝。

已有 TCP 会话无法迁移到新代理链。热更新关闭相关旧连接，由外部应用重连，不保证任意应用自动重试。DNS 仍沿用当前上游配置，启用链路不等于将所有 DNS 请求自动送入该链路。

## 链路预览设计

链式组显示独立标记和路径卡片，提供“链路预览”入口。按宽度使用横向或纵向编号步骤，避免跨行箭头指错方向，长节点名可换行，跟随现有浅色／深色主题。

预览分为两部分：

1. **配置路径**：切换 TCP／UDP 查看当前选出的物理节点、前置来源和静态协议限制。可以填写示例目标，点击“演示流向”播放逐跳粒子和节点高亮。动画不发起 DNS、访问、测速或探测，不代表连接成功，并遵从减少动画的系统偏好。
2. **实际连接**：读取活动连接中建立时保存的组依赖与节点路径，可选择具体连接与目标核对，并跳转活动的连接页。没有连接时显示空态，不伪造流量或自动发起请求；已有连接不会被重新标注为当前配置。

隐藏链式组中容易被误认为整链测量的单节点延迟和探测动作。单节点探测仍可在订阅页使用。

能力通过 `x-proxy-chain` 发布，组详情通过 `x-lemonvpn-chain` 返回配置路径和静态问题。预览读取不推进轮询策略的游标。连接的 `chain` 先列出依赖组 ID，再按实际转发顺序列出节点 ID。
