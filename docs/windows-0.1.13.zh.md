## GeoIP / GeoSite

共享规则引擎读取 V2Ray protobuf 格式，支持 `domain(geosite:cn)`、`qname(geosite:cn)`、`dip(geoip:cn)`、`ip(geoip:cn)`；IP 与域名条件可与端口、协议等条件组合。GeoSite 支持 full、suffix、keyword、regex、分类属性过滤；GeoIP 支持 IPv4 / IPv6 CIDR、反向分类与 private。缺少文件、分类不存在或正则无效会拒绝配置。

构建脚本固定官方 GeoIP / GeoSite 资产及 SHA256，核对摘要后缓存并打包。随包附带来源清单和许可证。用户更新的数据优先于随包数据；按需编译引用分类并缓存，不在每条流量上读取文件。Geo 数据内容参与配置代次，更新后旧 DNS 缓存不会冒充新规则结果。更新检查数据结构、校验引用分类；写盘或重建失败恢复原文件并保留生效快照。

## 进程条件

Windows 普通代理连接通过系统 TCP / UDP 归属表查询进程与路径；同一 UDP 端口有多个候选进程时保持未知，避免猜错。支持 `pname(chrome.exe)`，原始表达式也可使用完整路径。连接与流程保存判定时的进程信息。

TUN 内核按配置中的进程名称或路径识别原始应用，使用单独的认证 SOCKS 账号向共享引擎传递匹配信息，再由共享引擎按原有规则顺序判定。不会把桥接内核当作原始应用。配置变更会同步进程选择规则；服务端只接受有数量、长度限制的进程列表，不接受任意配置、出站地址或程序路径执行请求。

未知进程不伪造名称，依赖未知信息的否定条件也不视为匹配。TUN 转发后的来源地址仍是用户态入口观察值，不宣称恢复原始源 IP、PID 或所有应用的完整路径。进程归属适配本轮仅实现 Windows。

TUN 服务随包重建。已有旧服务需在用户安装新版本后，通过 TUN 模式的修复入口同步更新，才能使用新增进程传递协议；本轮未安装、重启或替换现有服务。

## DNS 响应规则

支持 `dns { routing { request { ... } response { ... } } }`，兼容已有直接 request / response 分块。响应规则支持 qname / GeoSite、qtype、upstream、IP / GeoIP 及逻辑组合；列表和 fallback 反映真实生效配置。

- `accept` 返回原始响应，保留其他记录及 EDNS。
- `reject` 返回成功但无答案的 NODATA 响应。
- 上游名表示改用该上游重新查询，随后再次评估响应规则。
- 最多访问三个不同上游，循环和超限返回 SERVFAIL；非 NOERROR 响应直接返回。
- API 查询、直接连接解析与 TUN DNS 转发共用响应规则；缓存按上游和配置代次隔离。

## 构建范围

仅做 TypeScript 类型编译、Rust 编译与 Windows x64 NSIS 构建，不运行自动化或联网运行测试，不启动新客户端、服务或内核，不切换系统代理、TUN 或电源状态。运行效果未在本轮验收。

内核继续使用固定版本的官方 mihomo ZIP，校验 SHA256 后提取为 `lemonvpn-kernel.exe`；macOS / Linux 名称为无后缀的 `lemonvpn-kernel`，这两个平台本轮不构建。正式发布和 Windows ARM64 延后。
