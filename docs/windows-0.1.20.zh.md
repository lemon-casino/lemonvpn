# Windows x64 0.1.20：DNS 动作能力与路由排序确认

## 本次日志检查

按请求只读查看现有进程、日志与 API 状态，未启动新客户端、内核或服务，未修改配置、代理或 TUN，也未主动刷新订阅。

日志中的订阅自动刷新失败对应网络超时 `os error 10060`，订阅保留已有节点并标记为 stale。检查时引擎正常响应，当前配置诊断没有错误；当时实际运行的出站模式为全局。这些是检查当时的状态，不代表新版本的运行验收。

## DNS asis 选项

原界面沿用了上游 UI 的 `asis` 动作，含义是把查询转交原始 DNS 目标；共享引擎没有这条处理路径，保存时会把它当成不存在的上游而校验失败。

本轮为引擎适配器增加 DNS 动作能力声明，规则页及 DNS 日志、查询结果等快捷新建入口都按能力生成选项。LemonVPN 当前请求规则提供已配置上游与 reject，响应规则提供 accept、reject 与通过上游重新查询。其他支持 asis 的引擎保留原选项。

手工配置使用不支持的 asis 时，后端返回明确的动作不支持诊断，不伪装成默认上游或原始目标转发。响应规则调用上游重新查询时，API 动作标记修正为 requery，并保留上游名称。

## 排序提交与回读

列表拖放增加 insert 落点回调的处理，与同表 reorder 回调共用一次保存流程。拖拽数据包含列表类型、当前组件标识及配置代次，拒绝其他表和旧配置的载荷，避免只出现拖动效果而没有提交。

表格使用稳定的元素引用；继续保持拖拽 Hooks 挂载，保存和确认期间通过禁用状态锁定。后端排序写入成功后记录范围和配置代次的日志。

保存后重新读取实际规则，按照规则表达式及顺序逐项核对，不能仅依据旧的行 ID 判断——行 ID 会随排序重新编号。回读确认后才显示保存成功；配置再次变化、顺序不一致、写入后读取失败分别提示并刷新，避免把乐观显示当成最终结果。

## 排序生效范围

规则页在实际运行全局或直连模式时提示：模式规则优先于普通路由规则，保存的普通规则优先级在规则模式下用于后续新连接。已有连接继续使用建立时的分流结果，不因排序被强制关闭或重建。模式规则与兜底规则仍保持固定。

本轮没有自动切换出站模式，也没有调整当前使用的规则顺序。
