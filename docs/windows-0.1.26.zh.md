# Windows x64 0.1.26：出站分类、双端策略组与活动链路动画

## 出站管理

菜单“策略”改为“出站”，页面分为“策略组／链式代理”两个页签，各自只显示自己的内容和新建按钮。打开某个出站的链接时自动切换到对应分类。原有 URL `/policies` 保留，避免破坏现有规则、搜索和卡片链接。

链式代理的前置、落地均可选择具体节点或策略组。两端引用策略组时分别使用各自的策略和 TCP／UDP 选择，前置与落地组均可继续引用链式出站，物理节点总数仍最多 8 跳。循环、重复节点集合和失效引用仍会被拦截。

新链路写入明确的两个引用，不再把落地变成固定节点过滤器：

```text
group {
  我的链路 {
    policy: fixed(0)
    dialer: '前置策略组'
    landing: '落地策略组'
  }
}
```

`fixed(0)` 在链路容器中不决定两端节点；实际选择由被引用的策略组完成。旧版本的单落地节点链路继续读取，编辑保存后转为 `landing` 引用。

## 热更新

配置更改仍走统一校验和原子提交。前置组或落地组的手动选择变化，立即关闭依赖该组、相应 TCP／UDP 传输的旧连接；旧拨号不能重新注册。自动选择的组在健康结果或连接质量更新前后比较选择，变化后同样通知依赖链路和界面，不等待下一次连接才发现变化。

随机和轮询策略继续按每个新连接选择；一次轮询游标前进不会反复中断所有正在运行的连接。用户更改这类策略配置时仍经过配置热更新边界。已有 TCP 会话无法迁移，关闭后交由应用重连。

自动选择同步不持有健康状态锁进入配置锁；共享观察器先比较配置代际，避免配置更新后再次无谓关闭新连接。原有策略工作线程和健康采集继续使用，不增加额外探测请求。

## 活动卡片与动画

直接改造活动中原有的策略组卡片和快速切换卡片。选择普通策略组时显示原有节点控制；选择链式代理时，标题和内容改为链路展示，支持 TCP／UDP 切换，两端引用及展开后的物理节点名称可查看。

动画只在活动卡片中显示：一个光点从本机出发，经过前置、落地，到达目标后消失，短暂停顿，再从本机出发到下一个目标，循环进行。固定画布避免内容跳动。实际连接中有与当前节点路径一致的记录时，目标使用记录中的域名／地址；没有记录时使用明确标记的示例网站。光点只示意流向，不表示真实数据包时间或连通性测量。

动画在卡片离开视口、文档隐藏、页签隐藏、编辑预览和系统要求减少动画时停止，不产生 DNS、网站访问或测速。逐帧只更新 SVG 光点与轨迹，不让整个页面每帧重新渲染。新建／编辑弹框不显示动画；管理页和规则追踪仅保留静态路径说明。

## 规则支持

路由规则的新建、编辑和连接／DNS 结果中的快捷新建，共用按“内置／策略组／链式代理”分类的出站选择器，写入的仍是出站名称。内核解析规则出站时，两端策略组按实际协议解析为完整链路，与活动、全局模式和普通连接使用同一套决定。

路由追踪响应新增可选的 `x-lemonvpn-chain` 路径信息。命中链路时展示完整的静态节点路径和协议限制，不把落地节点的单节点探测当成整链测量，也不推进随机／轮询策略的游标。预览仍不访问目标；规则优先级和全局／直连模式的受保护表达式保持原行为。

DNS 规则仍选择 DNS 上游或响应动作；链式代理属于流量出站，没有伪造成 DNS 响应动作。

## 构建边界

执行前端类型检查、相关 ESLint／格式检查、Rust workspace 编译检查和 Windows x64 安装包构建。按用户要求不运行测试或网络探测，不启动、安装或更新当前软件／服务，不修改当前用户配置、系统代理或 TUN。正式发布、ARM64 和其他系统构建继续延后。

安装包：`app/src-tauri/target/release/bundle/nsis/LemonVPN_0.1.26_x64-setup.exe`。
