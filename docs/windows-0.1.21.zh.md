# Windows x64 0.1.21：桌面拖放与流量配置热更新

桌面窗口使用 Tauri 的 `disable_drag_drop_handler()`，让 WebView2 将 HTML5 拖放事件交给前端。Tauri 默认的宿主拖放接管会阻止 Windows 前端的 HTML5 拖放；此前只调整列表回调仍不能解决这个入口问题。没有使用宿主文件投放事件的其他平台也统一交给前端处理。

## 热更新范围与连接处理

所有已接受的流量配置通过同一个发布函数生效，覆盖路由规则增删改、排序、默认重置，出站模式和全局出站，节点与订阅节点更新，策略组策略、默认成员、所属组与批量修改，DNS 上游和请求／响应规则，以及被规则引用的 Geo 数据变化。

函数比较实际执行值而非源文件摘要。流量配置改变后，在配置锁内发布新快照并作废旧连接、清理引擎 DNS 缓存；仅修改注释、格式或源位置不会关闭连接。非法配置和写入失败保留原快照及连接。已加载的 include 文件也检查修改时间和大小，不再仅观察主文件；外部文件变更由现有两秒轮询发现，页面保存通过提交接口直接生效。

策略组手动选择、固定与解除固定立即更新所选组的 TCP／UDP 连接，其他组及未选择的传输类型继续使用原连接；重复提交相同选择不会再次断开。API 如实返回 `connections_interrupted` 与关闭数量。正在拨号的决策携带配置及组选择版本，提交前开始、提交后才完成的旧拨号也会被作废，不能重新挂回旧路径。

TCP 已建立的传输无法无缝迁移到另一条代理线路。本版主动关闭旧连接，让客户端按新配置重连，不等待连接自然结束；无法替任意外部应用重放请求或保证其自动重试。UDP 旧 relay 在下一个数据包处理前释放并按新决策建立。HTTP、SOCKS、TUN 共用连接注册表与取消标记，空闲 TCP 泵也响应取消。

日志级别、记录开关与保留上限按运行时设置读取，提交后立即发出状态事件；主题及其他界面偏好仍在前端立即更新，不触发流量断开。策略和运行时设置变更主动发出事件；配置代次事件同时使连接、DNS 缓存、DNS 记录、出站计数等界面资源失效，避免只更新页面规则而保留旧数据。

调低 DNS 记录和流程记录上限时立即裁剪旧记录，无需等待下一次记录产生。DNS 缓存写入与发布共用配置锁，旧查询晚到也不能回填已失效的缓存。

配置锁释放后同步协议内核、TUN 内核的 DNS 缓存和 TUN 进程条件，使用固定版本的 [官方 DNS 缓存接口](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/hub/route/cache.go)。只清理解析缓存，保留 fake-IP 映射。Windows 管理员服务增加固定的 `flush_dns` 操作，沿用原有宿主身份及会话校验，不接受任意 API 路径。

已安装旧服务时，需要在 TUN 模式页面更新服务，才能使用新增的 TUN 内核缓存同步命令。本轮仅构建新服务，不执行安装或更新操作。同步失败保留待处理标记、后台重试并去重记录日志；状态页显示“配置已提交，内核同步尚未完成”及具体原因，能力扩展同时返回待同步状态和错误。

本次热更新指配置和流量决策生效，不包含在线替换应用二进制或前端代码。自动测速与负载均衡仍按各自算法选择线路，不因单个流量计数刷新关闭全部连接。
