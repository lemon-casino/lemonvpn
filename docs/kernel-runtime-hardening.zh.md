# 运行时内核增强（v0.1.45）

本轮修改位于桌面和 Docker 共用的 Rust 引擎及协议适配层，保留固定版本的官方 mihomo 二进制，不修改第三方内核源码。

| 项目 | 处理方式 |
| --- | --- |
| 协议配置长期累积 | 每分钟读取协议内核连接快照，回收超过 120 秒未使用且没有活动 TCP/UDP 链路的配置；仍被 UDP 会话引用的监听器继续保留。最多保留 1024 个同时使用的配置，快照或应用失败时保留原配置。 |
| DNS 总时限和竞速 | 查询、拨号、TLS、读取、重试及解析池回退共享截止时间；普通解析最多 10 秒，引导解析最多 12 秒。较快应答完成后取消其余查询，取消不记作节点故障。 |
| 连接容量 | 本机入口最多 512 个连接，代理会话共用 384 个配额，头部读取和管理请求各 64 个；局域网原有上限继续生效。线程创建失败也释放配额。 |
| 热更新读取阻塞 | 写入准备由单独锁串行处理，连接读取已接受的不可变快照；发布时短暂同步路由版本和缓存。文件准备及内核通信期间不占住配置读取锁。 |
| DNS 缓存删除 | 单条、域名和全量删除同步原始应答缓存与展示索引，取消匹配的合并查询，并阻止删除前的旧应答重新填入缓存。普通 DNS 清理保留 Fake-IP 映射。 |
| 预取状态 | 速率限制、并发限制、线程创建失败和上游失败均释放预取标记和配额，后续查询可以重新触发预取。 |
| 链式代理健康 | TCP 首个真实回传和无回传故障计入整条链路；UDP 首个应答和中继关闭也反馈链路状态。失败后退避 10 秒，允许一次恢复尝试。不能确定故障跳时不连带标记各节点失败。状态见 `/api/v1/runtime/apply` 的 `kernel.chain_health`。 |
| 双栈与多地址连接 | A/AAAA 并行查询，首个有效地址后最多等待另一族 200 毫秒；物理 TCP 最多两个候选交错尝试、全局最多 64 个拨号，并缓存 60 秒地址结果。协议内核使用明确的引导地址列表并开启 TCP 并发；有独立地址族出口时仍绑定对应物理接口。 |

取消会在 DNS 读写和合并等待的短轮询点生效；已经进入操作系统阻塞连接的拨号最多持续到其截止时间，退出后自动释放 socket 和配额。UDP 不重复发送用户数据做竞速。HTTP/HTTPS 订阅、节点凭据、TLS 验证、用户规则和 Fake-IP 排除名单不因本轮升级而改变。

验证范围是 Windows/Linux 编译检查、Linux release 构建和部署后的只读运行核对；按用户要求不运行测试、压力测试或业务探测。部署保留镜像和一致的数据备份，核对节点、分类绑定、DNS、局域网设置及手动选择。第三方节点入口发生的远端重置不能靠本轮代码保证消失。
